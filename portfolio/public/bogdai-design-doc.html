BogdAI design doc

A six-agent pipeline that reviews a contract and returns a typed risk report in which every finding cites its source. The design question was how much of that to trust to a language model.

  • RoleBackend, 96% of the Python source
  • EventMicrosoft Agents League 2026
  • Tests45, of which 41 mine
  • StackMicrosoft Foundry, Pydantic

Context

BogdAI was a team entry in the Reasoning Agents track of the Microsoft Agents League Hackathon. It analyses synthetic healthcare and pharma contracts against synthetic policy documents. I wrote the backend: the orchestrator, the six agents, the rule engine, the response schemas and most of the tests. A teammate built the HTTP endpoint and the interface.

Goals and non-goals

  • Goal: every finding is traceable to a clause and to the policy it breaches.
  • Goal: the pipeline runs end to end with no cloud credentials, so tests and demos never depend on a model being reachable.
  • Non-goal: a validated compliance product. All data is synthetic and the output carries a legal disclaimer.

Architecture

An orchestrator runs six agents in sequence: intake, clause extraction across 10 clause categories, grounding, risk reasoning, verification, and reporting. The report is validated against 9 Pydantic models with bounded score and confidence fields.

Contract text passes through intake, clause tagging and rule matching. In Foundry mode the grounding agent selects a source document, section and quoted evidence for each matched issue, and the reasoning agent returns three observation and inference steps with a risk level and score. Verification and reporting always run locally.

Guardrails

The verifier agent checks each finding for a citation, evidence, an excerpt and reasoning. It forces the human-review flag onto any high-risk finding that lacks one and scans the output for 7 unsafe-advice phrases. Ten further tests scan the data and source for patterns that look like personal data or credentials.

Evaluation

45 tests, of which 44 pass and 1 is an expected failure. On the first sample contract, Foundry mode returns 6 flags, all high, an overall rating of critical at a score of 87, with 6 citations and 0 unsupported claims. Local mode returns the same 6 flags as 4 high and 2 medium, at a score of 83.

Known gaps

  • The expected failure is in my code. The reasoning agent can still emit a high-risk finding without a grounded citation. The verifier catches it downstream; the reasoning step should not produce it.
  • No evaluation of model output. There is no golden set and no accuracy measurement for the grounding or reasoning stages.
  • No prompt-injection testing. Contract text and policy documents enter prompts unsanitised.
  • No continuous integration and no retries on model calls.

The source is public: github.com/anunjinb/bogdai-contract-risk-agent.
